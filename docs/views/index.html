llm-vs-small-models-extraction

Can a small model replace an LLM for structured extraction?

Four extractors read the same fictional booking documents and fill the same 13-field JSON schema. Each one is scored field by field, on layouts it trained on, on layouts it never saw, and on documents written to trick it.

the task

Turn a document into strict JSON

Every document is generated from a seed, so its correct JSON (the gold) is known exactly. Three layouts (email, invoice, note) are for training. Two more (chat, letter) are held out: they reword every label and put the balance before the deposit. A model that memorized where values sit fails on them.

the scores

    
How a prediction is scored

    
    
      
  • Field F1: per field, over 100 documents. A stated wrong value counts against precision and recall both.
    • 
      
  • Exact match: the share of documents with all 13 fields right. One wrong date makes the whole document wrong.
    • 
      
  • Valid JSON: the share of outputs that pass the strict schema (right keys, types and formats).
    •

result 2

    
What transfers to unseen layouts, field by field

    
Names and cities partly transfer for the trained models: the words themselves look similar in any layout. Dates and amounts do not, because the trained models learned their position and their label text, and the unseen layouts change both.

result 4

    
Cost, speed and accuracy in one table

    
Local models cost nothing per call, but they cost training time and they need labeled data. Seconds are wall-clock per document on an M1 laptop: the tagger runs on its GPU and the SFT model on its CPU. The LLM's seconds are the median API round trip over the adversarial run's live calls.

    

  


  

    
result 5

    
Can an LLM judge stand in for the gold?

    
Real documents have no gold JSON. A rubric judge sees only the document and the prediction, and says true or false per field. Here the exact scorer knows the truth, so the judge itself can be scored.

    
    
      
  • TPR: of the fields that are right, the share the judge accepts.
    • 
      
  • TNR: of the fields that are wrong, the share the judge catches.
    • 
      
  • Cohen's kappa: agreement beyond chance; 1 is perfect, 0 is no better than chance.
    • 
    

    

    
uv run eel judge

  


  

    
limits

    
What this does not show

    
    
      
  • The documents are synthetic and clean. Real documents add OCR noise, tables and many more layouts.
    • 
      
  • Each trained model is one run with one seed. Small differences between them are not significant.
    • 
      
  • The judge model and the extractor model are the same family. A different judge model could disagree differently.
    • 
      
  • The adversarial set is too easy for the LLM: it scores 100%, so the set cannot rank stronger models.
    • 
      
  • The judge is stricter than the scorer. The rubric asks for values exactly as stated; the scorer ignores case and accepts 1700 for 1700.00.
